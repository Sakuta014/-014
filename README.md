# 今天吃点麦

[在线体验](https://mai.sakuta.work/) · 独立参赛作品，非麦当劳官方产品。

打开即可使用套餐转盘、预算和忌口筛选、换一批吃的。未连接账号时使用官方公开套餐数据快照，金额明确标注为示例参考价，不代表当前门店可售或实时报价。

## 运行

需要 Node.js 22，无第三方依赖。运行 `npm start`，打开 http://127.0.0.1:5178 。不需要配置作者 Token。

需要实时菜单、核价和下单时，在连接窗口填写**访客自己的 MCP Token**。从[官方平台](https://open.mcd.cn/mcp)登录并激活后获取。站点不使用作者账号作为默认账号，也不读取 `MCD_TOKEN_FILE`。

Token 只临时保存在服务端内存，30 分钟后失效；浏览器使用 HttpOnly、SameSite Cookie，HTTPS 下启用 Secure。Token 不保存到浏览器存储、不写入订单记录，也不返回给页面。退出连接立即撤销当前会话；服务重启清除所有会话。

## 转盘与下单

- 默认预算 35 元，可调整或不限；报价有效期默认 5 分钟，可改。
- 官方套餐图片；每盘最多 6 份完整套餐。中心“转！”等概率抽取，“换一批吃的”更新候选，保留预算和忌口。
- 真实套餐使用官方默认子项及特制；排除需购买会员卡的套餐，不自动领券或使用个人券。
- 忌口仅基于可核实标签与名称规则，未知信息不视为满足；不提供过敏安全保证。
- 真实下单：选择套餐 → 核对门店、金额、官方取餐方式 → 用户明确确认 → 官方创建订单 → 打开官方付款页。网页不代付。
- 提交前重新核价，变价、超预算或过期会中止。网络超时需先去官方 App 核实，不自动重复提交。

每个 Token 的订单状态独立，记录在 `.local/visitors/`，只包含必要订单状态与 Token 摘要，不包含 Token 正文。记录需要持久保存以防重复下单；不得上传 GitHub、公开或随意清空未核实的订单。退出重连期间仍在处理的订单继续复用相同处理器。

## 部署

`dist/` 是前端，`server.mjs` 提供静态页面及会话保护的同源接口。纯静态托管可展示界面，但不能提供本项目的实时接口。代理固定官方上游，限制工具并校验 Origin；通用代理不开放创建订单，创建操作仅通过独立确认接口。

参考 `deploy/compose.server.yml`、`deploy/server.env.example` 和 `deploy/Caddyfile.example`。代码放 `app/`，持久订单目录为 `data/`，创建空挂载点 `app/.local`，将数据目录权限交给 UID 1000。Caddy 与应用加入 `gateway` 网络；应用不发布宿主机端口。`PUBLIC_ORIGIN` 精确设置为 HTTPS 域名。

首页不设置登录或体验密码。所有实时业务接口要求访客自己的有效会话；不配置共享 Token，不挂载作者凭证文件。部署时只打包版本控制中的源码，保留服务器数据目录。

## 验证

运行 `npm test`。覆盖筛选、落点、套餐默认配置、核价、防重复提交、支付域名校验、代理限制、公开首页、访客隔离、会话过期和退出重连。使用模拟响应验证创建订单；自动测试不创建真实订单。

此前已在南京门店验证工具发现、菜单、完整套餐核价及下单准备。测试价格不代表未来价格。公开访客版本不使用作者 Token 做自动测试。
